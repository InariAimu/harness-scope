# LM Studio 兼容

[文档索引](README.md) · [使用指南](USAGE.md)

适配器 `lmstudio` 读取 LM Studio 0.4.x 桌面会话，已针对 0.4.26 的原生结构验证。默认目录为 `~/.lmstudio/conversations`，Windows 对应 `%USERPROFILE%\.lmstudio\conversations`。现有安装首次升级会添加该来源，目录存在时启用；用户之后关闭或删除来源不会被自动恢复。

## 本机桌面范围

只发现 `*.conversation.json`，支持会话子文件夹。不扫描 `server-logs`、`.internal/api-prediction-history`，也不采集其他终端调用本机模型服务产生的请求。这里的本机来源指本机桌面会话目录；原生文件没有可靠的发起设备字段，用户自行复制到该目录的外来会话无法自动判断原设备，应将此类归档留在采集目录之外。

会话列表展示标题、创建和最后活动时间。阅读器支持文本、思考内容和附件引用；不自动加载附件文件，不提供修改、删除或恢复运行入口。有多个消息版本时默认显示 LM Studio 当前选择的版本，可在「消息版本」切换阅读和导出，原始文件不变。首版不承诺还原所有 MCP 工具专用界面。

## 用量与计价

每个带有效 `genInfo.stats` 的生成步骤计为一次请求，包括重新生成后未选中的版本。以原生 `stepIdentifier` 作为稳定事件身份，重复扫描、会话副本或切换选中版本不重复计数。追加版本增加新事件，已有事件修订维持身份。

输入、输出、合计分别取 `promptTokensCount`、`predictedTokensCount`、`totalTokensCount`，必须是有效整数且合计相符；不从文本长度、文本块 Token 或会话级 `tokenCount` 推算。缺失统计、未知结构或写入中断保留诊断，已有事实不会被不完整读取撤销。

LM Studio 原生总量没有缓存分类，输入表示完整 prompt Token，不能解释为已知的非缓存输入。现有非空计数契约中的缓存及推理字段使用占位 0，专用界面显示缓存未提供、无缓存命中率；不据此声明真实缓存或推理消耗为零。这是该来源保留原始总量的明确约定，不能套用到需要缓存计费拆分的云端来源。思考正文可阅读，但不把其文本块计数伪装成完整推理用量。

所有费用保持未计价，即使模型匹配本地价表或执行重新计价，也不产生估算费用；不将本地模型视为已确认免费。

## 时间、同步与增量

会话创建及活动时间使用原生字段。生成事件时间使用已识别的步骤 ID 毫秒前缀，界面标明这一依据；它代表原生步骤创建时间，不承诺是 HTTP 请求开始时间。未识别的 ID 格式暂缓采集，不使用导入时间补造。

耗时和首字延迟使用 `totalTimeSec`、`timeToFirstTokenSec`，非法或不合理的计时不展示。这些计时仅存入本机计时表；用量、模型、事件时间和未计价状态可沿用现有 v4 协议同步，不要求旧服务器理解新增计时来源。消息正文、配置和附件引用不进入用量同步或持久用量读取缓存。

增量复用已有文件检查点：未变化的文件跳过，变化后重读完整用量投影并按生成身份更新。LM Studio 官方将 JSON 视为内部结构，后续格式变化应更新适配器和合成回归样本，不能静默以零代替缺失统计。[官方会话存储说明](https://lmstudio.ai/docs/app/basics/chat)
