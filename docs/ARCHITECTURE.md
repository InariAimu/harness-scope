## 模块边界

```text
原生日志 / SQLite
        ↓ HarnessAdapter
解析结果与诊断 → 采集、身份协调、价格快照 → 本机 SQLite
                                               ↓ 查询投影
                                     Tauri / 本机 HTTP API
                                               ↓
                                           React 界面

本机事实与待传队列 ↔ 自部署同步服务器 ↔ 其他设备镜像
供应商查询 → 本机额度采样 → 显式关联的共享订阅历史
```

| 模块 | 职责 |
| --- | --- |
| [harness](../crates/core/src/harness/mod.rs) | 格式发现、原生身份、用量与会话投影 |
| [engine](../crates/core/src/engine.rs) | 调度采集、计价、查询和命令执行 |
| [store](../crates/core/src/store.rs) / [schema](../crates/core/src/schema.sql) | 事务、事实、队列和持久化状态 |
| [query_store](../crates/core/src/query_store.rs) / [query](../crates/core/src/query.rs) | 索引查询、聚合、分页和展示口径 |
| [accounts](../crates/core/src/accounts.rs) | 官方查询、自定义查询、采样、预算和共享历史 |

适配器拥有格式知识，核心不依赖 Tauri。会话正文按本机来源读取，不写入用量同步记录；用量采集与阅读投影分别优化。

## 用量事实

`UsageRecord` 以 `(device_id, id)` 定位事实，包含修订号、删除标记、工具、原生会话／事件身份、时间、模型、Token 分类和费用快照。原生供应商、计时和请求元数据为可选字段，来源必须可验证。

- 原生 ID 优先；回填和解析器修复沿用稳定身份，不能通过换 ID 重复计数。
- 累计 Token 转成事件增量；继承历史、分段副本和重复快照由各适配器去重。
- `input` 表示新增输入，与 `cacheRead`、`cacheWrite` 互斥；`reasoning` 是 `output` 子集，`cacheWrite1h` 是 `cacheWrite` 子集。
- 不完整或损坏的来源保留旧事实并重试，不能把读取失败解释为整批删除。
- 默认区分未知与零；Copilot 的兼容字段限制单独记录在[导入说明](COPILOT_IMPORT_DESIGN.md)。

费用优先使用可确认的原生报告，否则按价格来源估算；没有匹配价格则未知。金额使用十进制语义，保存实际单价、来源及计价口径。价表更新不自动改写冻结费用，显式重新计价通过修订同步。订阅估算使用的 API 等值不代表现金账单。

## 存储与查询

- `records` 保存本机事实；`outbox` 保存待确认的修订；`remote_records` 保存其他设备的镜像。
- `usage_index`、`record_timings` 是事务维护的查询投影。查询使用独立只读 WAL 连接，分页按需读取快照和计时。
- 来源指纹、解析版本、读取缓存、Codex 分段映射及迁移清单保存在本机，不进入同步 DTO。
- 后台采集和供应商刷新分别调度。前端按实际用量版本刷新和复用查询缓存。

会话正文和长块使用独立缓存与分页引用。删除支持的会话前先采集、提交用量，且来源须稳定至少 60 秒；采集失败则取消删除。删除正文保留已发生的统计，统计修正使用单独的撤销修订。

## 请求用量同步

服务面向单用户，使用 Bearer token，远程连接要求 HTTPS。上传每批最多 200 条，下载默认每页 500 条；支持 gzip，解压后上传上限为 5 MiB。

1. 客户端检查 `/health` 的协议与记录能力，然后上传持久 outbox。
2. 服务器以设备和记录 ID 验证修订：新修订替换旧值，同修订同内容幂等，同修订不同内容拒绝。
3. `server_changes` 保存每条记录最新的单调序号位置，关联当前事实生成下载页；删除墓碑保留。
4. 客户端在同一事务应用远端变化并推进游标，确认上传时只移除对应修订。
5. 服务器实例变化时重建远端镜像与游标，本机事实和墓碑重新进入待传队列。

本机记录与自身服务器镜像不重复汇总。设备身份边界之外没有原生日志副本的全局去重，因此复制同一来源到多台设备分别采集可能重复统计。

## 订阅历史同步

成功的官方／自定义查询先写入本机采样历史。用户将账号明确关联到共享订阅后，通过独立队列和 `/v1/subscriptions/*` 接口同步已有及新增真实采样。

共享采样有稳定身份与来源设备，同 ID 不同内容被拒绝。历史按实际采样时间合并；凭据、查询脚本、路由关联、价表和手动套餐配置留在各设备。当前额度卡片仍使用本机查询结果。

同一固定窗口内的回退读数可以从趋势和估算中筛除，原始采样仍保留；请求 Token 事实不参与此筛选。历史和请求都要完成同步，跨设备测算才有足够数据。详细操作和限制见[供应商与订阅](PROVIDERS.md#跨终端订阅历史)。

## 版本与兼容

| 标识 | 当前定义 | 含义 |
| --- | --- | --- |
| 应用版本 | 根 `Cargo.toml` 的 workspace 版本 | 产品与构建身份 |
| SQLite schema | v6 | 本机和服务端表结构 |
| 请求用量协议 | v4 | 请求事实、可选计时和元数据白名单 |
| 订阅历史能力 | `subscription_history_v1` | 独立订阅目录与采样同步 |
| Claude 记录能力 | `claude_request_timing_v2` | 新 Claude 计时和请求元数据 |

能力由服务端健康检查声明。旧服务不支持某类记录时，客户端保留对应待传项并提示升级，不丢弃字段后提前确认。先升级服务端和代理路由，再升级读取新记录的客户端；具体步骤见[服务器说明](../server/README.md)。

数据库升级前制作一致性备份；回退应用需恢复对应版本数据库，不能只换旧程序。设备 ID、远端游标和冻结费用不应因常规升级重置。
