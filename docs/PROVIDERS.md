# 供应商与订阅

[文档索引](README.md) · [使用指南](USAGE.md)

本页从原 README 拆出账号与订阅操作。官方返回的余额／额度、日志费用估算和用户手填账期资料分别保存与显示。

## 添加账号

在「供应商 → 添加账号」选择类型。同一类型可添加多个账号。

| 类型 | 查询凭据 | 显示内容 |
| --- | --- | --- |
| DeepSeek | API Key | 官方原币总余额、充值余额、赠金 |
| OpenCode Go | API Key | 官方额度窗口、剩余比例与重置时间 |
| OpenAI／Codex | 本机已有 Codex 登录 | App Server 返回的套餐标识和额度窗口 |
| 自定义供应商 | 按需填写 Base URL、API Key 和查询脚本 | 提取器返回的余额或额度 |

Codex 默认检测桌面版或 PATH 中的程序，也可指定程序和数据目录。查询使用 `account/read`、`account/rateLimits/read`，不发送模型请求；只保存白名单额度字段及身份摘要，认证仍由 Codex 管理。缺失窗口不视为无限额度。

套餐名称、月费、币种、本期开始和下次续费手动记录，也可不配置查询凭据。官方窗口重置时间与账单续费日期分别显示，不互相覆盖。

## 侧栏与刷新

侧栏的箭头展开账号列表，账号卡片进入对应详情，刷新按钮刷新所有配置了凭据的账号。可在编辑器中选择是否显示在侧栏；排序模式允许上移／下移并确认保存。显隐和顺序仅在本机保存，不改变账号查询策略。

「余额／额度自动刷新」分别配置前台和后台间隔：默认 60／300 秒，0 关闭对应自动刷新，其余支持 15–86400 秒。前台指账号在供应商页被选中且窗口有焦点；其他状态使用后台间隔。查询由后端调度，关闭应用后停止；手动刷新仍受同账号并发保护，自动查询最多四个并行，失败重试至少间隔 60 秒。

失败时保留上次成功结果并标记错误；到期或未知窗口显示等待刷新，不自行恢复为满额。

## 关联用量

按「工具 + 原始 provider ID」将日志路由关联到账号，可选择已采集路由或手动添加。同一路由只属于一个本机账号；映射用于本机及所有已同步设备的关联用量，不受统计页设备筛选影响。账号名用于展示，原始 ID、会话文件和历史事实不改写。

日志不能区分同一路由曾使用的不同 Key／订阅。使用不同订阅时需要不同路由，未知来源也不能仅凭模型名推断归属。路由关联需在每台设备分别配置。

「订阅周期」按手填开始与续费日期统计。Go／Codex 的「本周额度周期」使用有效官方周窗口的重置时刻往前七天，缺失或过期时先刷新，不改用自然周替代。所有区间使用设置中的统计时区。

## 历史与分析

每次成功且被接受的刷新保存一条真实采样，即使余额未变也保留。记录包含实际时间、时区、精确金额／比例、窗口及配置版本；失败或已被新配置淘汰的响应不产生采样。历史不补造、不自动裁剪，删除账号配置仍保留历史。

「历史与分析」支持余额或额度窗口、最近 24 小时／7 天／30 天及分页加载。普通缺失读数之间可连接有效采样；确定的重置起点以空心 100% 节点开始新线段。该节点是推算值，不计入真实采样数，也不能作为额度测算端点。同一固定窗口内的异常余量回升可从图表和测算中筛除，原始记录仍保留。

额度测算使用两个真实采样之间的消耗百分点与关联请求参考费用：

```text
窗口等效总额度 = 同期模型参考费用 × 100 ÷ 消耗百分点
```

至少间隔一分钟、变化一个百分点；不足五个百分点时提示取整敏感性。测算检查身份、配置、套餐、窗口和数据覆盖，缺价、旧日汇总或未知窗口不能强行推算。结果代表该区间模型与档位组合的 API 等值，不是官方现金余额，各窗口也不能相加。

开发接口为 `provider_account_history` 和 `provider_account_estimate`。历史查询按账号支持 `startAtMs`（含）、`endAtMs`（不含）及 `beforeSequence` 游标，每页 1–500 条，默认 100 条；`observedAtMs` 使用毫秒，窗口重置时间使用 Unix 秒。同一毫秒按本机序号稳定排序，序号不表示跨设备时间先后。

## OpenCode Go 参考估算

「额度续航与每日预算」结合官方余量、当前 Go 规则和已同步关联请求，估算当前强度可持续时间及重置前预算；「用量模拟器」计算假设请求的窗口占用，不发送模型请求。

混合模型按各请求的模型、上下文档位、缓存组成及峰谷时段分别计算。未匹配模型、未公布价格和旧日汇总会排除并提示覆盖不足；不使用订阅月费代替模型额度。预算依赖样本数、采样跨度及官方快照新鲜度，缺少条件时保持未知。

内置规则见 [opencode-go-catalog.json](../crates/core/resources/opencode-go-catalog.json)。在「编辑规则」维护 JSON，或复制查询提示词核对后更新。数据库旁的 `harness-scope.opencode-go.json` 为草稿，需「从文件载入 → 校验并应用」才生效。规则中的检查日期和来源应随更新维护，本文不重复列动态价格。

更新规则不自动重算历史费用；活动配置和草稿不参与同步，已写入记录的价格快照随用量传输。

## Codex 参考预测与 Fast

预测面板提供「概览」「目标重置」「窗口与采样」「参考配置」。默认按有效官方窗口起点统计近期关联用量，也可选择固定采样时长；所有模型共享相应额度，不能把各模型预测相加。

参考套餐、模型额度、来源、检查日期与倍率见 [codex-allowances.json](../crates/core/resources/codex-allowances.json)。参考值可以采用配置中的外部样本或理论倍率，不代表官方保证额度。数据库旁的 `harness-scope.codex-allowances.json` 是草稿，需在编辑器载入并应用；不覆盖手动账期资料或冻结费用。

自动校准使用同一可验证身份、套餐、额度桶和重置窗口中的真实采样，结合同期已同步请求拟合消耗速率。账号切换、配置或窗口改变会切断区间；样本不足、缺价、回退读数或过期快照不能作为可靠依据。关联共享订阅后可使用合并历史；未同步用量和供应商计费延迟会影响结果。

「目标重置」允许按统计时区或固定 PST（UTC−8，不切换夏令时）指定目标时刻，计算重置前的参考强度。目标不能早于当前时刻或晚于官方周重置，不提前使用未来补充额度。

当前内置 `subscriptionSpeed` 将订阅内 Fast 消耗倍率配置为 2.5，购买 credits 倍率配置为 2；这是本地参考规则，应连同其来源和检查日期维护。订阅预测只使用订阅倍率，混合档位先归一化，避免重复相乘。界面的 API 折算按参考单价计算，不将倍率直接乘入历史费用，也不保证 Fast 的实际速度提升。档位的日志证据与未知值规则见 [Codex 说明](CODEX.md)。

## 自定义查询

自定义供应商可以只用于显示名称和路由归属，也可独立启用查询。配置 Base URL、API Key、超时和以下形态的 JavaScript：

```javascript
({
  request: { url: "{{baseUrl}}/usage", method: "GET", headers: {} },
  extractor(response) {
    // 按实际响应结构取值；多项结果需要各自稳定的 id。
    return { id: "balance", remaining: response.balance, unit: "USD" };
  }
})
```

`{{baseUrl}}`／`{{apiKey}}` 在请求数据中展开，不注入脚本源码。请求支持 GET／POST、字符串或 JSON body，目标必须与 Base URL 同源，不跟随重定向，遵循应用网络设置。上例路径和响应字段仅示意，需按目标接口调整。

提取器返回单个对象或 1–20 个对象数组。可用字段包括 `id`、`planName`、`remaining`／`used`／`total`、`unit`、`usedPercent`；金额可用十进制字符串，缺失保持未知。可选 `resetsAt`（Unix 秒或含时区 RFC 3339）、`durationMinutes`、`windowType`（`fixed`／`rolling`）；只有明确固定窗口才生成推算满额起点。

QuickJS 无文件、进程和直接网络能力。每个计算阶段最多 500 ms，内存 16 MiB，响应 256 KiB、结果 32 KiB，HTTP 超时 2–30 秒。测试查询只预览草稿；保存后的成功刷新才写历史。改变查询配置或 Key 会清除旧快照并更新配置版本，保留旧历史。本功能不切换 CLI 供应商或接管请求转发。

## 跨终端订阅历史

1. 第一台设备在「编辑账号 → 跨终端订阅历史」创建共享订阅，保存后完成同步。
2. 其他设备先同步订阅目录，再将各自账号关联到同一共享订阅。
3. 各端持续采集并同步请求与额度历史，再查看合并后的分析。

绑定会上传该账号已有及后续真实采样，需确保历史属于同一订阅。同名账号不会自动合并；每台设备的一个共享订阅最多关联一个账号，绑定后不能改绑，换订阅需新建本地账号。

允许各端同时使用并独立采样。稳定采样 ID、来源设备、持久队列和分页游标保证重试不重复；迟到样本按实际时间合并。当前额度卡片仍来自本机刷新，共享历史不覆盖凭据或当前查询缓存。

凭据、Codex 路径、自定义脚本、路由关联、手动套餐和价表仍在各端配置。只有已上传的请求能参与测算，待传清零不证明离线设备没有额外使用。

此功能需要 schema v6 和服务端 `subscription_history_v1` 能力；请求用量协议仍为 v4。先升级服务端及两条订阅代理路由，再升级客户端。旧服务下请求同步可继续，订阅历史保留待传并提示升级；部署见[服务器说明](../server/README.md)。

## 凭据存储

API Key 单独保存到数据库旁的 `.provider-keys` 目录，不出现在账号查询返回值、用量事实或共享历史里。Windows 使用当前用户 DPAPI 加密；Unix 使用 0700 目录和 0600 文件权限，尚未接入系统钥匙串。仅备份数据库不包含 Key，换 Windows 用户或设备后需重新填写。编辑时 Key 留空保留原值，可显式清除；删除账号和 Key 不删除历史用量。
